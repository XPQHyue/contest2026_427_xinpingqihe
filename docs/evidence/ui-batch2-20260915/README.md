# UI 第二批 (a)(b)(c)：原始传感器迷你曲线 / 倾角指针盘 / 秒表环形进度（2026-09-15）

> 截图为**模拟器**（goldfish-arm64-v8a-ap-phywear，390×450，与真机同分辨率同布局）与**真机**（黄山派 SF32LB52）两套。
> 模拟器 IMU 是**合成波形**（`phywear_sensors.c`：`ax=600·sin`、`ay=120·sin`、
> `az=1000+300·sin` [mg]、`gx=20000·sin` [mdps]，0.8 Hz），**数值不得当测量结果引用**。
> 倾角/秒表页的截图用了 `inclinebench` / `timebench` 的**注入波形**，同样是合成数据。

## 2. 改了什么

### (a) 原始传感器三轴页 —— 数值 + 迷你实时曲线

- **布局**（`phywear_raw.c`）：3 行「轴字母 + 48 px 大数字」→ **一行三列数值**
  （轴字母 20 px 用 X/Y/Z 系列色、数值 28 px）+ 下方 **358×186** 曲线区，
  竖直切成 X/Y/Z 三条泳道（各 62 px），与数值列左右对齐；左下 `+/-满量程`、右下 `8 s`。
  数值不再带单位（列宽 126 px 放不下 `+1234.5 dps`），单位统一标在右上角。
- **复用 `pw_scope`**：新增 `pw_scope_set_lanes_i16()`（多泳道 + int16 样本 + 单块缓冲），
  每页只占 **1 个 scope 槽位**，**不新增 lv_malloc 缓冲**。
- **历史样本**：`int16_t g_raw_hist[3][80]`（80 × 100 ms = 8.0 s），**三轴页共用一份**，
  进页清零（曲线只表示"本次进入后连续采样的 8 s"）。
- **自动量程**：取**整条窗口**峰值按 1-2-5 步进（加速度 1..8 g、陀螺 20..2000 dps、地磁 100..30000 mG）。

### (b) 倾角页 —— 指针式角度盘

- **13 根刻度短线**（`lv_line`，-90°..+90° 每 15°，每 30° 一根长粗刻度）+ **指针**（`lv_line`）
  + 盘心圆点；0° 在正上方，±90° 满偏，正值向右。
- 刻度按当前角度**逐格点亮**（只对状态变化的刻度写颜色）；指针 12.5 Hz 节流 +
  位移 <1° 不重绘（静止的手表零绘制开销）。
- `lv_line` 的**对象框收紧到线段自身包围盒**：`lv_line_set_points()` 失效的是整个对象框，
  保持 168×168 会让每次移针重画整盘。
- **不用 `lv_arc`**：实测软件圆弧绘制把本页帧率从 ~26 拉到 23（见 §4）。

### (c) 秒表页 —— 环形计时进度

- `lv_arc` 满环 + **环心实时秒数**（本页原来没有实时读数）：满环 = "上次间隔"
  （还没有就取 2.0 s），跑动中按 `elapsed/ref` 填充；超过上次间隔 → 满环 + 换"偏慢"色（橙）。
- 停下时满环但用暗色（读作"上一次间隔已完成"，不是"正在进行"）。
- **只在值与颜色真的变了才写对象**：`set_style_arc_color()` 每次调用都会让整个圆弧对象
  重绘（156×156），闲时每 100 ms 白刷一次很吃亏。

## 3. 曲线幅度校验（像素级，可复现）

```bash
python3 verify_curve_scale.py sim-raw-accel.png accel
python3 verify_curve_scale.py sim-raw-accel.png gyro
```

按系列色取出曲线像素，用泳道几何把行号反算成物理量，与合成波形对照：

| 轴 | 实测（从截图反算） | 合成波形期望 | 结论 |
|---|---|---|---|
| 加速度 X | −0.62 .. +0.62 g | ±0.60 g | ✅ |
| 加速度 Y | −0.11 .. +0.11 g | ±0.12 g | ✅ |
| 加速度 Z | +0.69 .. +1.28 g | 0.7 .. 1.3 g | ✅ |
| 陀螺 X | −19.13 .. +19.13 dps | ±20 dps（100 ms 采样最大值 ≈19.4） | ✅ |
| 陀螺 Y/Z | 泳道中线（反算 −0.91 dps） | 0 | ✅（±0.5 px 取整） |

> 曾用临时插桩日志验证 `hist[79] == round(v*k)` 与送给数值标签的 `v` 完全一致
> （日志：`[phywear][dbg] ... v=-2224/-444/2884 h79=-2224/-444/2884`）。模拟器截图里偶尔看到的
> "曲线比数字提前/滞后一个采样（100 ms）"是 **adb 在 LVGL 正在写 `/dev/fb0` 时读帧**造成的
> 读撕裂，不是渲染逻辑问题。

## 4. 帧率与内存（真机实测，同页同 bench，30 s 窗口）

`fps` = 本窗口 LVGL 实际推屏帧数/秒；`loops/s` = GUI 主循环次数（**不是**帧率）。
本批为此把原来"只在 `bench` 模式打印"的帧率探针接进了 30 s 心跳。

| 页面 | fps 改动前 | fps 改动后 | loops/s 前→后 |
|---|---|---|---|
| 原始传感器（a，曲线） | 12（1 次） | **12 / 12** | 63 → 59 |
| 倾角（b，指针盘） | 27 / 27 / 25 | **25 / 25 / 25** | 27 → 25 |
| 秒表（c，环形进度） | 11 / 10 / 10 | **9 / 9 / 9** | 61 → 59 |

- **(a) 无帧率退化**（12 → 12）。
- **(b) 落在改动前区间内**（改动前 25~27，改动后稳定 25）。过程中对比过三种实现：
  `lv_arc` 圆弧 → 23；去掉圆弧改刻度 → 24；修正构建后 → **25**。
- **(c) 稳定少 1 帧（10.3 → 9）**。原因：环心读数落在圆弧对象的包围盒内，读数每 100 ms
  变一次就会连带重绘圆弧。**已知可选修法**：把圆弧也改成"分段刻度环"（与 (b) 同一手法），
  预计回到 ~10 fps，代价约 +320~384 B SRAM —— 本批**未做**，留作后续按需取舍。
- 主循环次数全线 −3~−4（每帧 CPU 变多），但帧率由 100 ms / 50 ms 的 tick 节拍决定，未受影响。

> ⚠️ **帧率探针在真机上是本批新接的**：原来的 `pw_fps_init()` 只在 `/dev/fb0` 可 mmap 时
> 装回调，而**真机没有 `/dev/fb0`（只有 `/dev/lcd0`）**，所以真机 `fps` 恒为 0。
> 现改为挂 `LV_EVENT_RENDER_READY`（`lv_refr.c` 只在本轮真的有区域重绘时才发），
> 模拟器/真机都成立，且不再替换 flush 回调（不干扰板级推屏路径）。

## 5. 本批发现并修复的三个问题

1. **自动量程抖动（本批新引入，已修）**：最初用"当前瞬时样本"算峰值 → 正弦过零点时
   量程掉档，出现"数值写 `+/-50 dps`、曲线却按 20 dps 画"。改为取整条 80 点窗口峰值后自洽。
2. **`pw_ui_root()` 屏幕栈泄漏（既有隐患，顺手修）**：只把 `g_scr_n` 归零、不删除栈里的旧屏
   → 旧屏的 `pw_scope` 槽位不归还；`phywear cap root` 反复重建到第 3 次起
   `pw_scope: out of slots (6 in use)`，曲线静默消失。现先删屏再重置。
3. **`restore_code.py` 后必须动一下源文件再编译（本次踩坑，已写进 `docs/07`）**：
   恢复快照会**保留快照里的 mtime**，若比构建目录里的 `.o` 旧，ninja 会**跳过重编** ——
   本次因此烧出一个"倾角页有指针盘、原始传感器页却还是旧版式"的混合固件，
   靠 `nm <obj> | grep pw_scope_set_lanes_i16` 才发现。修法：`touch apps/examples/phywear/*.c *.h` 再构建。

## 6. 已知限制（如实）

- 模拟器**无地磁驱动**（`/dev/mag0` 打开失败），地磁页数值恒为 `--`、曲线为空；
  该页已由**真机**补齐（−1308/+431/+234 mG，量程 `+/-2000 mG`）。
- 三轴页曲线**只在当前页采样**（省 I2C），切页清空重来；不保留跨页历史。
- 秒表环形进度的"参考值"是**上次间隔**（没有上次间隔时取 2.0 s 常数）—— 这是本批
  选定的语义，不是用户可配置的"目标时间"。
- 本批**未做**：3 个 FFT 频谱页、LVGL 矢量图形、逐页动效、圆角/阴影大铺开、任何渐变。
- 秒表页 fps 少 1 帧（见 §4），可选修法已列出但未实施。
